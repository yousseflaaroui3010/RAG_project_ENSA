# Frontend contract

Concrete shapes and numbers. The process is in the phase-4 skill body.
`rules-scoped/02-frontend.md` binds above this file, and `screen-states`
governs which states must exist.

## Types

No `any`. No `@ts-ignore`. If a type is genuinely unknown, use `unknown` and
narrow it, so the compiler makes you handle the branch instead of letting it
through.

Check the data shape at the edge, where it enters the app. A backend change then
fails loudly at the boundary instead of quietly rendering an empty screen three
components deep.

## Every async action has three states

Loading, success, and an error a person can act on. "Something went wrong" is
not actionable. Say what failed and what they can do next.

## State

Never mutate. Local state for anything only one component cares about. A shared
store (Zustand) for anything two or more need.

Reaching for a global store to avoid passing one prop is how a store becomes a
junk drawer.

## Resilience

Optional chaining and defaults on anything that arrives from outside. Error
boundaries around data-driven UI, so one bad record does not blank the page.

## Speed

Lighthouse 90 or better. LCP under 2 seconds. Lazy-load anything below the
fold.

Judge it on real visits at the 75th percentile, split between phone and desktop,
not on the machine that built it.

## Styling

Design tokens, not inline styles. A colour written in twelve components is
twelve edits when the brand changes.

## Generated clients

API clients are generated by Orval from the OpenAPI spec. Never hand-write a
fetch wrapper for an endpoint the spec already describes; the hand-written one
drifts the first time the spec changes.

## Scaffolding

Start from a template: `pnpm create vite <name> --template <preset>`. Presets
include react-ts, vue-ts, svelte-ts, solid-ts, lit-ts, preact-ts, qwik,
vanilla-ts. `pnpm create vite-extra` carries more.

Do not spend tokens rewriting boilerplate the generator already produces.
Generate, then customise.
